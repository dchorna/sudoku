# Технічне завдання
## Проєкт: «Судоку з перегородками» (Consecutive Sudoku) + класичний режим

---

## 1. Загальна інформація

Гра реалізує **два режими**:

1. **Класичне судоку** — стандартна сітка 9×9, стандартні квадрати 3×3, без додаткових позначень.
2. **Судоку з перегородками (Consecutive Sudoku)** — та сама сітка 9×9 з квадратами 3×3, але між сусідніми (по горизонталі/вертикалі) клітинками може стояти жирна лінія — **перегородка**. Вона несе інформацію:
   - **Якщо між двома сусідніми клітинками є перегородка** — числа в них відрізняються рівно на 1 (наприклад, 4 і 5).
   - **Якщо перегородки немає** — числа в цих клітинках НЕ можуть відрізнятись на 1 (тобто не можуть бути послідовними).

Перегородки завжди показані **повністю** — тобто для кожної пари сусідніх клітинок гравець бачить, є там перегородка чи ні. Саме відсутність перегородки — це так само важлива інформація, як і її наявність.

Правила рядків/стовпців/квадратів 3×3 — стандартні класичні (без повторів 1–9), для обох режимів однакові. Перегородки — це додаткове обмеження, яке існує лише в режимі 2.

---

## 2. Мета проєкту

Розробити застосунок, який:
- дозволяє грати у два режими: класичне судоку і судоку з перегородками, кожен на трьох рівнях складності;
- генерує коректні поля з **єдиним розв'язком** для обраного режиму й рівня;
- надає **покрокові логічні підказки** з поясненням;
- демонструє CSP-формалізацію та пошук у просторі станів (backtracking, MRV, forward checking).

---

## 3. Технологічний стек (фіксовано)

- **Мова:** Python 3.11+
- **Backend / логіка:** чистий Python (model/generator/solver/hint engine — незалежні, тестовані модулі)
- **UI:** легкий web-інтерфейс — Flask (або FastAPI) + HTML/CSS/vanilla JS. Поле — HTML-таблиця; перегородки рендеряться як жирні межі між клітинками (CSS border між `<td>`).
- **Тести:** pytest, покриття для model/generator/solver.
- **Без зовнішніх ML-бібліотек** у базовій версії (нейромережевий модуль — опційний розділ 10).

## 4. Функціональні вимоги

### 4.1 Вибір режиму та рівня
- FR-1: На старті гравець обирає режим — **«Класичне»** або **«З перегородками»** — і рівень складності — **легкий / середній / складний**.

### 4.2 Генерація поля
- FR-2: Генерація повного коректного поля 9×9 (стандартні правила рядок/стовпець/квадрат 3×3) методом backtracking.
- FR-3 (лише режим «з перегородками»): після заповнення поля — обчислення перегородок: для кожної пари сусідніх клітинок перегородка є тоді і тільки тоді, коли їхні значення відрізняються рівно на 1. Перегородки — детерміновано похідні від значень поля, не обираються окремо.
- FR-4: Видалення чисел з повного поля так, щоб залишкова головоломка мала **рівно один розв'язок** з урахуванням усіх діючих обмежень режиму (класичних, а для режиму 2 — ще й обмежень від перегородок, включно з інформацією про їхню відсутність).
- FR-5: Рівень складності визначається набором технік, потрібних для розв'язання без вгадування, — точні критерії в п. 5.

### 4.3 Гра
- FR-6: Введення/видалення чисел у порожніх клітинках.
- FR-7: Миттєва підсвітка конфліктів: класичні (рядок/стовпець/квадрат) + у режимі «з перегородками» — порушення правила суміжності (перегородка, а різниця ≠ 1; або немає перегородки, а різниця = 1).
- FR-8: Визначення моменту повного й коректного заповнення поля (перемога) + таймер.
- FR-9: Кнопка «нова гра» з вибором режиму і рівня.
- FR-10 (опційно): збереження/завантаження поточної гри.

### 4.4 Система підказок
- FR-11: За запитом — пошук клітинки, яку можна однозначно заповнити логічним методом, з поясненням чому (класичні техніки — п. 6.6; для режиму «з перегородками» — ще й техніки з п. 6.7).
- FR-12: Підказки впорядковані за складністю техніки — від найпростіших до складніших; видається перша, що «спрацювала».
- FR-13: Кнопка «розв'язати повністю».
- FR-14: Лічильник використаних підказок за гру.

## 5. Рівні складності (конкретні критерії)

### 5.1 Режим «Класичне судоку»

| Рівень | Відкритих клітинок | Обов'язкові техніки | Заборонені техніки |
|---|---|---|---|
| Легкий | 40–45 | Naked Single, Hidden Single | Naked/Hidden Pair, Pointing Pairs |
| Середній | 30–35 | + Naked Pair, Hidden Pair | Naked/Hidden Triple |
| Складний | 24–28 | + Naked Triple, Pointing Pairs | — (без вгадування, лише логічні техніки) |

### 5.2 Режим «Судоку з перегородками»

Через додаткову інформацію від перегородок (особливо від їхньої відсутності) поле розв'язується при значно меншій кількості відкритих цифр, ніж класичне — це нормальна властивість жанру (класичний варіант жанру взагалі допускає 0 стартових цифр, коли розв'язок повністю визначається самими перегородками).

| Рівень | Відкритих клітинок | Обов'язкові техніки | Заборонені техніки |
|---|---|---|---|
| Легкий | 20–25 | Naked Single, Hidden Single, Wall Forced Value, No-Wall Elimination | Consecutive Pair, Consecutive Chain |
| Середній | 8–14 | + Consecutive Pair (п. 6.7) | Consecutive Chain |
| Складний | 0–6 | + Consecutive Chain (ланцюгове виведення через кілька перегородок підряд) | — |

Алгоритм перевірки рівня при генерації (застосовується до FR-4/FR-5 в обох режимах):
1. Згенерувати повне поле → видаляти клітинки, підтримуючи єдиність розв'язку з урахуванням активних обмежень режиму.
2. Після кожного видалення прогнати `HintEngine` в режимі «розв'язати, використовуючи тільки логічні техніки, без backtracking-вгадування» і зафіксувати застосовані техніки.
3. Зупинити видалення, коли досягнуто цільової кількості клітинок і набір технік відповідає межам таблиці для обраного рівня.
4. Якщо розв'язання вимагає технік «складніше дозволеного» — відкотити останнє видалення і спробувати інше.

## 6. Алгоритмічна частина (ядро ШІ)

### 6.1 Формалізація як CSP

- **Змінні:** 81 клітинка поля.
- **Домен:** кожна змінна ∈ {1..9}.
- **Базові обмеження (обидва режими):** `all-different` для кожного рядка, стовпця та квадрата 3×3 (27 обмежень).
- **Додаткові обмеження (лише режим «з перегородками»):** для кожної пари орт. сусідніх клітинок (a, b) — бінарне обмеження:
  - якщо є перегородка: `|value(a) − value(b)| = 1`
  - якщо перегородки немає: `|value(a) − value(b)| ≠ 1`

### 6.2 Генерація повного поля (Backtracking + randomization)

```
function FillBoard(board):
    cell = SelectEmptyCell(board)
    if cell is None:
        return True
    values = [1..9], shuffled randomly
    for v in values:
        if IsConsistent(board, cell, v):   // рядок/стовпець/квадрат 3×3
            board[cell] = v
            if FillBoard(board):
                return True
            board[cell] = 0
    return False
```

### 6.3 Обчислення перегородок (лише режим «з перегородками»)

```
function ComputeWalls(board):
    walls = {}
    for each pair of orthogonally adjacent cells (a, b):
        walls[(a, b)] = (abs(board[a] - board[b]) == 1)
    return walls
```
Перегородки повністю визначені готовим полем — не обираються довільно.

### 6.4 Розв'язувач з евристиками (основний AI-модуль)

- **MRV** — обирати клітинку з найменшою кількістю допустимих кандидатів.
- **Forward Checking** — після заповнення клітинки видаляти значення з доменів клітинок того ж рядка/стовпця/квадрата; у режимі «з перегородками» — додатково застосовувати обмеження суміжності до доменів сусідів (звужувати або виключати кандидатів згідно п. 6.1).
- (Опційно, бонус) **Algorithm X / Dancing Links** для класичного режиму.

```
function Solve(board, walls=None):
    if board is full: return board
    cell = cell with Minimum Remaining Values (MRV)
    if cell has 0 candidates: return Failure
    for v in candidates(cell):
        board[cell] = v
        propagate(board, cell, v, walls)   // класичні + (якщо walls задані) суміжні обмеження
        result = Solve(board, walls)
        if result != Failure: return result
        undo propagate(board, cell, v, walls)
        board[cell] = 0
    return Failure
```

### 6.5 Перевірка унікальності розв'язку

1. Запустити `Solve()` з активними обмеженнями режиму — знайти перший розв'язок.
2. Продовжити пошук із забороною щойно знайденого розв'язку (або рахувати кількість розв'язків, зупиняючись при 2).
3. Якщо розв'язків більше одного — повернути видалену цифру і спробувати видалити іншу клітинку.

### 6.6 Класичні техніки підказок (обидва режими)

| Техніка | Опис |
|---|---|
| Naked Single | У клітинки залишився лише один можливий кандидат |
| Hidden Single | У межах рядка/стовпця/квадрата число може стояти лише в одній клітинці |
| Naked Pair | Дві клітинки групи мають однаковий набір з 2 кандидатів → ці кандидати виключаються з інших клітинок групи |
| Hidden Pair | Два числа можуть стояти лише в тих самих двох клітинках групи → інші кандидати в цих клітинках виключаються |
| Naked Triple | Аналогічно Naked Pair, але для трьох клітинок і трьох кандидатів |
| Pointing Pairs | Кандидат у квадраті обмежений одним рядком/стовпцем → виключається з решти клітинок цього рядка/стовпця поза квадратом |

### 6.7 Техніки для режиму «з перегородками»

| Техніка | Опис |
|---|---|
| Wall Forced Value | Якщо клітинка має перегородку із заповненим сусідом зі значенням v — її кандидати звужуються до {v−1, v+1} (з урахуванням меж 1–9) |
| No-Wall Elimination | Якщо між клітинкою і заповненим сусідом зі значенням v перегородки немає — кандидати v−1 і v+1 виключаються з цієї клітинки |
| Consecutive Pair | Для двох ще не заповнених сусідніх клітинок з перегородкою між ними — залишаються лише ті пари кандидатів, що відрізняються на 1; несумісні кандидати виключаються з обох клітинок |
| Consecutive Chain | Ланцюгове застосування Wall Forced Value / No-Wall Elimination через кілька перегородок підряд (наприклад, три клітинки поспіль із перегородками) — дозволяє звузити кандидатів навіть коли жодна клітинка в ланцюгу ще не заповнена, лише за рахунок меж діапазону 1–9 |

`HintEngine` перевіряє техніки по черзі від найпростішої (спершу 6.6, потім — якщо активний режим «з перегородками» — 6.7 в порядку складності); перша, що «спрацювала», видається як підказка з поясненням. Цей самий перебір використовується і в п. 5 для контролю складності при генерації.

### 6.8 (Опційно) Нейромережевий модуль — лише за наявності часу

- **OCR розпізнавання дошки з фото/скану** — невелика CNN (MNIST або власний датасет) розпізнає цифри з фото паперового судоку.
- **Класифікатор складності** — невелика модель (MLP / дерево рішень) передбачає суб'єктивну складність на основі ознак (к-сть відкритих клітинок, набір потрібних технік, глибина backtracking).

Окремий необов'язковий розділ роботи, не підміняє основний детермінований solver.

## 7. Нефункціональні вимоги

- NFR-1: Генерація поля будь-якого режиму й рівня — не більше кількох секунд.
- NFR-2: Пошук підказки — практично миттєвий (< 1 с).
- NFR-3: Код модульний: окремо model, generator, solver/hint engine, UI; логіка перегородок ізольована так, щоб класичний режим працював без жодних змін у цих модулях (просто без переданого `walls`).
- NFR-4: Інтерфейс простий, перегородки візуально чітко відрізняються від звичайних меж клітинок.

## 9. План реалізації (етапи)

1. Модель дошки + класичні правила (рядок/стовпець/квадрат 3×3).
2. Генератор повного поля (backtracking).
3. Модуль перегородок (`wall_generator.py`) + розширення моделі під обмеження суміжності.
4. Solver з MRV + forward checking, що підтримує обидва режими; перевірка унікальності.
5. `HintEngine`: спершу класичні техніки (6.6), потім техніки перегородок (6.7).
6. Видалення клітинок з контролем рівня складності для кожного режиму окремо (п. 5).
7. Web-інтерфейс: вибір режиму/рівня, поле з відображенням перегородок, підсвітка помилок, кнопки підказки/розв'язати.
8. Тести (pytest) для model/generator/solver, окремо для обох режимів.
9. (Опційно) ML-розширення.
10. Документація коду + короткий звіт/презентація для захисту.

## 10. Критерії оцінювання / тестування

- Коректність генератора: 100% полів — валідні, з єдиним розв'язком, що відповідають критеріям складності з п. 5, для обох режимів.
- Коректність розв'язувача: успішно розв'язує будь-яке валідне поле для обох режимів.
- Коректність перегородок: для будь-якого згенерованого поля режиму 2 — перегородка є тоді і тільки тоді, коли сусідні значення відрізняються на 1 (жодних розбіжностей).
- Якість підказок: підказка завжди логічно обґрунтована й відповідає реальному стану поля.
- Продуктивність: генерація + розв'язання — у межах секунд (NFR-1, NFR-2).
- Покриття тестами: model, generator, solver, включно з обома режимами.
